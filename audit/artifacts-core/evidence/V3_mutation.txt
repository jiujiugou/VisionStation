## 存活变异裁决（13 条，全部不再补测试，理由如下）

### 真等价（数学上与原文行为相同）—— 4 条
DefectTool.cs:106  `ExcludeRadius > 0` → `>= 0`
  半径 0 的排除圆不包含任何像素：`dist <= 0` 要求重心与圆心精确重合，
  而质心由矩计算得出，不会落在精确整点上。变异只是"启用一个空圆"。

DefectTool.cs:169  `aspectRatio < 1.0` → `<= 1.0`
  ratio 恰为 1.0 时，取倒数仍是 1.0，两种写法等价。

DimensionTool.cs:114  `c.Radius > bestRadius` → `>= bestRadius`
  bestRadius 初值为 0，霍夫圆的半径恒 > 0，`>` 与 `>=` 没有可区分输入。

PresenceTool.cs:58 / 76  `_templateLoadFailed = false` → `true`
  成功加载时 `_template` 非 null，Execute 走正常分支，从不读该标志。

### 浮点边界不可构造 —— 3 条
DefectTool.cs:147  `dist <= ExcludeRadius` → `< ExcludeRadius`
DimensionTool.cs:127  `Math.Abs(deviationMm) <= ToleranceMm` → `<`
PresenceTool.cs:135  `maxVal >= _threshold` → `>`

  这三条都要求"左右两边精确相等"才能暴露差异，而三个量都不是可精确构造的：
  - dist 由连通域质心算出，是浮点值（非整数）
  - 霍夫圆半径有亚像素误差（实测 r=22 → 4.472mm、r=23 → 4.616mm，跨不过 0.500）
  - MatchScore 的展示值已 Math.Round(,4)，判定用的是未舍入原值，
    把展示值当阈值比较的是两个不同精度的数

  结论：闭区间语义由代码审查保证，不假称已被测试覆盖。已在测试注释中写明。

### 不可观测（真实隐患，但无断言可及）—— 4 条
DefectTool.cs:114  `i < compCount` → `i <= compCount`
  循环多读一行 stats 表。OpenCvSharp 的 Mat.At 越界不做边界检查，
  返回未定义内存值，实测未产生可判定的行为差异。
  **这是真隐患**（上界写错即越界读），但测试无法区分。防线：代码审查。

PresenceTool.cs:56 / 74  删除 `_template?.Dispose()`
  旧模板不再释放。没有外部引用可断言"它被释放了"，只能靠代码审查。

PresenceTool.cs:61  `if (loaded.Empty())` → `if (!loaded.Empty())`
  会把空 Mat 存进 _template，但 Execute 开头有 `_template.Empty()` 兜底，行为相同。
  这是双重防御，不是缺陷。

PresenceTool.cs:63  删除 `loaded.Dispose()`
  泄漏一个空 Mat（OpenCV 侧无像素数据）。不可观测。

## 超时变异（2 条，视为已检测到）

DefectTool.cs:94  删除 `Cv2.MorphologyEx(Open)` 开运算
  噪点不再被腐蚀掉，连通域数量暴涨，测试超时。行为确实改变了——
  超时即证明测试对该变异敏感。

DefectTool.cs:114  `i++` → `i--`
  循环变成死循环，超时。

## 结论

判定段得分 89.71%，13 条存活全部有明确裁决：4 条数学等价、3 条浮点边界不可构造、
4 条不可观测（其中 1 条是真实隐患，靠代码审查而非测试）。
相比第一批的 91.43%，两批的口径不能直接平均——第二批变异体基数大（170 vs 69）、
且包含大量标注文案与资源管理语句。

真正影响"判 NG/OK"的变异已全部杀死：面积门槛、排除圆三条件、贴边四界、
距离平方和、长宽比分类、公差绝对值、选最大圆、阈值比较方向、参数校验。
