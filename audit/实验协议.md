## 一、这个实验要回答的三个问题

| # | 问题 | 为什么值得问 |
|---|------|------------|
| Q1 | 这套三阶段法**能不能跑**（而不是只能描述） | 表单填得满不代表跑得动；要看门禁会不会真的卡住 |
| Q2 | 它比「直接问 AI 找故障」**强多少** | 没有对照组，方法好坏只能靠感觉 |
| Q3 | 三个门禁**拦得住什么、拦不住什么** | 门禁全绿但漏掉真故障，是最危险的失败模式 |

## 二、预先注册的假设（可证伪）

- **H1（形式）**：门禁脚本能在产物不合规时稳定返回非零退出码，且不需要人工解读。→ 已验证一次（空产物 3 阻断）。
- **H2（效果）**：三阶段产物在「真实故障召回率」上不低于自由提问（对照组）。证伪条件：召回率低于对照组。
- **H3（质量）**：三阶段产物的「证据准确率」（code_ref 真实且相关）显著高于对照组。证伪条件：低于 95%。
- **H4（本实验最想验的）**：形式完备 ≠ 内容完备。**预期结果是「网格 100% 覆盖、金标准召回却不高」**——若真是如此，说明这类方法解决的是「不可追溯」，不解决「想不到」。

## 三、范围

**在范围内**（33 文件 / 3071 行 / 20 个有行为的单元）：
`src/VisionStation.Core`、`Devices`、`Storage`、`Service`

**范围外**：`App`（WPF/MVVM/Dispatcher）、`Watchdog`、测试、GoldenSetRunner、第三方库内部。

**为什么这么切**：这四层是可以脱离 UI 复现的运行时核心；UI 层的绑定与调度独立成第二轮。代价是——**所有后台事件的实际消费者都在 App 层**，跨线程时序只能靠契约推断。此代价已写入 `index.json.coverage_claim`，并在门禁 3 中以 `UNVERIFIED` 显式保留。

**网格规模**：(20 单元 + 22 交互) × 9 类失效 = **378 格**。

## 四、金标准（不参与分析的一方）

来源：项目内**真实发生过的故障痕迹**——`crash.log`、`diag.log`、`Logs/*.log`（2026-07-17 至 2026-10-19，10 个文件）。

机械抽取结果：44 行命中 → 归并 **38 组**故障指纹，封存于 `ground-truth/incidents.json`。

**纪律**：阶段 1 分析与阶段 2 造约束期间**不打开**该文件。抽取脚本只打印计数不打印内容，已执行。

**局限（必须先说）**：日志只记录"发生过"的故障，不记录"潜伏未触发"的故障。因此召回率的天花板是 38，且**它是下限而非全集**——真实故障集远大于 38。这个指标只能横向比较（三阶段 vs 对照组），不能当作绝对质量。

## 七、三阶段产物（字段级）

**FailureCatalog.json**
```
{id:"F-001", target:"U08", category:"阻塞", status:"FOUND|N/A",
 trigger, impact, code_ref:"path:line@Symbol",
 reachability:"REACHABLE|CONSTRUCTIBLE|THEORETICAL", severity:"H|M|L",
 na_reason /*status=N/A 时必填*/, unknown:bool}
```

**RequirementCatalog.json**
```
{id:"R-001", from:["F-001"], provenance:"PRODUCT_REQ|ARCH_RULE|CODE_AS_IS|ASSUMPTION",
 control:"PREVENT|DETECT|RECOVER|ACCEPT",
 statement, scope, trigger, criterion, deadline_ms,
 verification_method, verifiable:bool, falsifier /*ASSUMPTION 必填*/}
```

**VerificationReport.json**
```
{results:[{id:"V-001", req:"R-001", status:"PASS|FAIL|UNVERIFIED|NOT_RUN",
 evidence:"path", note, retry_of?}]}
```

## 八、门禁（脚本判，不接受口头完成）

`scripts/gate_check.py`，三关：

1. **覆盖对账**：378 格每格必须有 F 或 N/A+实质理由；`code_ref` 的**文件存在、行号在范围内、符号在文件中能找到**；REACHABLE 类必须有 trigger/impact。
2. **约束合法**：provenance 四值合法；`CODE_AS_IS` 不得作为 PASS 依据（现状合理化防线）；scope/trigger/criterion 三要素齐全；每条 FOUND 的 F 必须被至少一条 R 处理。
3. **验证收口**：每条 R 至少 1 个 V；状态必须四态之一；PASS/FAIL 必须附存在的证据文件；**未执行/无法验证必须留痕，不得省略**。

退出码非零 = 该阶段不许进入下一阶段。当前状态：空产物 → 3 阻断，退出码 1。

## 九、失败判据（什么结果算「这方法不行」）

- M2 < 对照组召回 → **H2 证伪**，方法在本项目上不增值。
- M3 < 95% → 产物证据不可信，比发散更危险（发散你看得见，假证据看不见）。
- M4 < 60% → 阶段 2 退化成文档，无法进入验证。
- M1 = 100% 且 M2 < 30% → **门禁只证明填满了，不证明想到了**。这是我预期最可能出现的结局，也是本实验最有价值的输出。
