## 三、工具框架（目标 30 分）—— 核心改动

### 3.1 Tool 抽象——最重要的架构升级

当前三个检测器各自为政，没有统一接口。改为：

```csharp
/// <summary>
/// 检测工具统一接口
/// 所有检测器（Blob、模板匹配、尺寸测量、OCR……）都实现此接口
/// </summary>
public interface IVisionTool
{
    /// <summary>工具名称（显示在界面上）</summary>
    string Name { get; }

    /// <summary>
    /// 执行检测
    /// 输入：灰度图 + ROI 区域 + 工具参数
    /// 输出：检测结果
    /// </summary>
    ToolResult Execute(Mat grayImage, RoiRegion roi, ToolParameters parameters);
}

/// <summary>
/// 工具参数基类（每种工具自己继承）
/// </summary>
public abstract class ToolParameters
{
    /// <summary>参数唯一标识（用于序列化）</summary>
    public string Id { get; set; } = Guid.NewGuid().ToString("N")[..8];
}

/// <summary>
/// 工具执行结果
/// </summary>
public class ToolResult
{
    public bool IsOk { get; set; }
    public string Summary { get; set; } = "";           // 一行文字摘要
    public Dictionary<string, double> Metrics { get; } = new(); // 指标
    public List<Annotation> Annotations { get; } = new();       // 标注（画什么）
}

/// <summary>
/// 标注 —— 检测结果的可视化表达
/// </summary>
public abstract class Annotation { }

public class RectAnnotation : Annotation
{
    public Rect Rect { get; set; }
    public Scalar Color { get; set; }
    public string? Label { get; set; }
}

public class CircleAnnotation : Annotation { /* 圆心、半径、颜色 */ }
public class ContourAnnotation : Annotation { /* 点集、颜色 */ }

// V1 只做三种，文字标注附在 Rect/Circle 的 Label 字段上就够了
```

### 3.2 现有三个检测器改造

```
Before:                          After:
PresenceDetector.Detect()        PresenceDetector : IVisionTool
DimensionDetector.Detect()       DimensionDetector : IVisionTool
DefectDetector.Detect()          DefectDetector : IVisionTool
```

每个只需要把 `DetectionResult` 换成 `ToolResult`，把画标注的逻辑移到 `Annotations` 列表里。

### 3.3 Tool 列表可配置

```json
// tools.json
{
  "tools": [
    { "type": "Presence",  "enabled": true, "roi": "Presence",  "params": { "threshold": 0.70 } },
    { "type": "Dimension", "enabled": true, "roi": "Dimension", "params": { "tolerance": 0.50 } },
    { "type": "Defect",    "enabled": true, "roi": "Defect",    "params": { "areaMin": 50 } }
  ]
}
```

- 启动时加载 → 按顺序创建 `IVisionTool` 实例
- `Pipeline` 遍历列表执行
- 可扩展：将来加 `OCR`、`Barcode` 直接加一条记录

## 四、Pipeline（目标 20 分）

### 4.1 当前状态

```
Pipeline.Run(image, rois, calib) → 硬编码执行三个检测器 → InspectionReport
```

可以工作，但不能动态配置。

### 4.2 目标状态

```
Pipeline.Run(image)
    │
    ├── Tool[0].Execute() → ToolResult
    ├── Tool[1].Execute() → ToolResult
    ├── Tool[2].Execute() → ToolResult
    │       │
    │       └── Annotations → 画标注叠加图
    │
    └── InspectionReport { Results: List<ToolResult> }
```

Pipeline 只知道"有一个工具列表，按顺序执行"。不关心每个工具内部做什么。

### 4.3 异常处理约定

单个 Tool 执行抛异常时，Pipeline 不崩溃：

```csharp
foreach (var tool in _tools)
{
    try
    {
        var result = tool.Execute(gray, roi, parameters);
        results.Add(result);
    }
    catch (Exception ex)
    {
        // 该 Tool 返回 NG，Pipeline 继续执行下一个 Tool
        results.Add(new ToolResult
        {
            IsOk = false,
            Summary = $"{tool.Name} 异常: {ex.Message}"
        });
    }
}
```

**原则**：一个 Tool 崩了不连累其他 Tool，不中断整条线。

### 4.4 动态编排——可选加分项

提供一个简单配置方式：

```csharp
// PipelineConfig.cs
var config = new PipelineConfig();
config.Add(new PresenceTool { Roi = "Presence" });
config.Add(new DimensionTool { Roi = "Dimension" });
config.Add(new DefectTool { Roi = "Defect" });
```

将来做 UI 界面配 Tool 流程时，底子已经有了。

## 八、面试话术（你自己讲的）

> "VisionStation 是一个 5 层架构的工业视觉检测工作站。Core 层是纯算法，Devices 层抽象了相机和触发源，Service 层做编排，App 层是 WPF 的 MVVM 界面。
>
> 我实现了一个 IVisionTool 抽象 —— 所有检测工具统一接口，Pipeline 遍历工具列表执行。目前有三个工具：模板匹配、尺寸测量、Blob 缺陷检测。加新工具只需要实现接口，Pipeline 一行不改。
>
> 坐标系方面，我单独抽了一个 CoordinateMapper 做屏幕坐标和图像像素坐标的转换，支持 Uniform 拉伸、Zoom 缩放、平移。ROI 编辑器直接在图像上拖拽画框，坐标存 JSON，自动对接到 Pipeline。
>
> 没用硬件，用 FileCamera 模拟工业相机读图片，WebcamCamera 接 USB 摄像头。将来接海康 SDK 只需要写一个 HikCamera 类实现 ICamera，其他代码不动。"
