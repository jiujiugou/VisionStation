# 产线意外走查 —— 2026-10-21

> 目的：不是证明"它能跑"，而是找出**它坏了以后说不说得清为什么**。
> 判定标准只有三条：**不可归因** / **静默** / **无护栏**，任意一条成立即记为缺口。
> 本文所有结论都来自实跑日志，不是推演；复现命令见 §6。

---

## 1. 怎么做的

界面点不了（本机 `Add-Type` / UIAutomation 被安全策略拦截），所以不用"模拟点击"，用**工装**：
`tools/ClosureProbe` —— 一个不带窗口的控制台程序，引用 `VisionStation.App`，调用
`AppHost.InitializeAsync()`。它走的是**与真启动完全同一条路径**：配置绑定 → 设备连接 → 自检 →
VM 订阅 → 建库，只是不 `Show()`。

每个场景在 `artifacts/runs/<场景名>/` 下**独立数据根**运行（db、图片、日志、配方副本全在里面），
互不污染，也不碰仓库里的测试素材。

> 顺带撞到的第一条：`AddViews` 里有护栏 —— **拿不到 UI 同步上下文就拒绝启动**。
> 设计是对的（没有上下文，检测结果会回到线程池去更新界面），代价是端到端只能人工点。
> 工装为此起了一个真 Dispatcher 并通过了这道检查。

## 2. 八个场景的实测结果

| # | 场景 | 注入方式 | 实测表现 | 判定 |
|---|---|---|---|---|
| 0 | 基线 | 20 帧 @300ms | 触发 20 / 跑完 16 / 入库 16 / 存图 16 | 丢 4 帧**无痕**（已修） |
| 1 | 图片目录没了 | `ImageFolder` 指向不存在路径 | 设备 1/2；日志有 `[FileCamera] 文件夹不存在: <路径>`；随后 20 次 `采图失败-无图像`；自检仍写「有设备离线」 | **不可归因**（见 F2） |
| 2 | 图片损坏 | 塞一个 0 字节 bmp | `[ERR] [FileCamera] 读取失败,图片为空: <文件名>` → 该帧跳过，其余继续（15/20 完成） | 可接受 |
| 3 | 尺寸对不上 | 混入一张 300×300 | 该帧被 sensor 校验拒绝，日志 `[配方]` 说明；其余帧正常（15/20） | 可接受 |
| 4 | 存图目录被占 | 用同名**文件**占住 `InspectedImages` | **启动直接失败**：`IOException: Cannot create '...\InspectedImages' because a file or directory with the same name already exists.` | **不可读**（英文异常，见 F5） |
| 5 | 配方 JSON 损坏 | 把 `default-2448.json` 写成非法 JSON | 回退内嵌配方 → 与 2448 画面不匹配 → **20 帧全部被拒，判定 0、入库 0**；只有第一条 `[配方]` 是 ERROR，之后降 Debug | **静默**（见 F3） |
| 6 | 数据库被锁 | 另开连接 `BEGIN EXCLUSIVE` 占 6 秒 | 一帧卡在 SaveAsync 约 5 秒（`Default Timeout=5`），期间 19 次触发全丢；最后抛 `database is locked` | **静默 + 卡顿**（已部分修，见 F1） |
| 7 | 节拍压到 50ms | `TimerIntervalMs=50`，跑 6 秒 | 触发 117 / 跑完 17 → **丢掉约 100 帧（85%）**，界面上完全看不出来 | **静默**（已修） |

> 基线里判定全是 NG，与软件无关：合成素材的孔是**椭圆**（172×138），霍夫圆检不出。
> 这一轮看的是"链路在异常下的行为"，不是检测准确率。

## 3. 已修的两条

### F1 丢帧现在会留痕

**问题**：`RunFrameAsync` 里 `Interlocked.Exchange` 判重入后直接 `return` —— 不排队是对的
（排队只会让界面永远追不上现场），但**丢掉多少帧没有任何痕迹**。节拍 50ms 时丢 85%，日志一行都没有。

**修法**（`InspectionPageViewModel.ReportDroppedFrame`）：累计计数 + **5 秒节流汇总**，
日志 WRN 一条 + 界面日志面板一条。逐帧记会把日志刷没，反而埋掉真问题。

**复跑证据**（fast-tick）：

```
13:26:20 [WRN] 上一帧未完成，已丢弃 1 次触发（累计 1 次）：单帧耗时超过触发间隔
13:26:25 [WRN] 上一帧未完成，已丢弃 85 次触发（累计 86 次）：单帧耗时超过触发间隔
```

**测试**：`丢帧必须留痕_节流期内只汇总一条警告`（用 `ListLogger` 断言"这件事被说出来了"）。

### F1b 数据库被锁时说人话

**问题**：SQLite `database is locked` 冒到界面是一串英文 EF 堆栈，现场只看到"检测异常"四个字，
且**不知道这条结果到底存没存**。

**修法**（`InspectionRepository.RunAsync`）：捕获 `DbUpdateException + SqliteErrorCode 5`，翻译成
「数据库被锁定，本条检测结果未入库（可能有另一个实例、后台清理或外部工具正在写同一个 db）」。

**复跑证据**（db-locked）：

```
[ERR] 检测异常
System.InvalidOperationException: 数据库被锁定，本条检测结果未入库（可能有另一个实例、后台清理或外部工具正在写同一个 db）
 ---> Microsoft.Data.Sqlite.SqliteException (0x80004005): SQLite Error 5: 'database is locked'.
```

## 4. 还没修，如实记成欠账

| # | 缺口 | 为什么现在不改 |
|---|---|---|
| **F2** | 自检把"目录不存在"报成**「有设备离线」**；`DeviceManager` 把 `Connect` 的真实原因吞掉，只留"已调用 Connect 但仍未连接" | 要改 `ICamera`/`DeviceManager` 契约（暴露 `LastError`），牵动两个测试替身与自检输出，属独立切片 |
| **F3** | 配方回退后与画面不匹配 → 整站**一帧都不检**，而 ERROR 只报一次、之后降 Debug。稳态下界面显示"运行中"，实际什么都没测 | 需要**常驻告警**（状态栏红条 + 计数），是产品设计，不是一行代码 |
| **F4** | 存图失败 5 秒内连续 N 次会升级告警（已有），但**存图只是变慢**时没有任何提示 | 需要延迟/耗时监控，属观测性改造 |
| **F5** | 存图目录被占 → 启动抛**英文 IOException**，且软件整体不启动 | "不启动"对产线是正确语义（停线优于静默丢图），但报错应中文化并指出是"存储路径"问题 |
| **F6** | 无 UI 上下文就不能启动 → **端到端无法自动化**（只能人工点） | 属架构取舍，不在本轮 |
| **F7** | DB 卡顿时单帧会**卡满 5 秒**（默认超时），期间界面不动 | 缩短超时会牺牲慢盘兼容性，需要权衡 |

## 5. 这轮真正发现了什么

不是"它不够健壮"。八次意外里，**没有一次崩溃**（除启动期那条，且是明确拒绝启动）。
问题全部集中在同一处：**它知道自己坏了，但没有告诉现场。**

- 丢帧：知道（判重入），不说 → 已修
- DB 锁：知道（异常），说成英文堆栈 → 已修一半
- 配方回退后不匹配：知道（每帧拒），只吼一次
- 采图失败：知道（FileCamera 已记文件名），上层只说"无图像"

这正是 `sensor` 校验、连续存图失败告警想要解决的那一类问题，只是还没覆盖完。

## 6. 复现

```powershell
cd D:\Code\VisionStation\tools\ClosureProbe
dotnet build -v q
cd bin\Debug\net8.0-windows

.\ClosureProbe.exe base
.\ClosureProbe.exe fast-tick
.\ClosureProbe.exe db-locked
.\ClosureProbe.exe no-image-dir
.\ClosureProbe.exe corrupt-image
.\ClosureProbe.exe sensor-mismatch
.\ClosureProbe.exe image-dir-is-file
.\ClosureProbe.exe recipe-corrupt
```

每个场景打印一行 JSON：`fired`（触发数）、`judged`（跑完帧数）、`dbRows`（入库）、
`images`（存图）、`dropWarn`（丢帧告警条数）、`logErrors`（ERROR 行数）。
数据根在 `artifacts/runs/<场景>/`，可直接翻日志原文对账。
