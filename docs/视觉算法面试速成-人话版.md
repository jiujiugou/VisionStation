## 1. 预备概念（10 分钟看懂）

- **像素 (Pixel)**：图像最小单元。640×480 图 = 640 列 × 480 行小方格。
- **灰度图 (Grayscale)**：每个像素一个值 0~255，0=纯黑，255=纯白。你的 3 个工具全部先转灰度。
- **阈值 (Threshold)**：一刀切的分界值。"灰度 < 128 → 白" = 把暗的地方挑出来。
- **边缘 (Edge)**：灰度突变的地方（明→暗），通常是物体轮廓线。
- **ROI**：图像上一块矩形子区域，只在这块里做检测 → 提速 + 减少干扰。
- **Blob**：连成一片的前景区域，可理解为"一团对象"。
- **轮廓 (Contour)**：Blob 的边界线。
- **形态学 (Morphology)**：对黑白图做"变胖/变瘦"操作，用于去噪。
- **模糊/滤波 (Blur/Filter)**：把每个像素和邻居按权重求平均，让图变平滑、去噪。

这些就是全部前置知识了。

## 2. PresenceTool — 模板匹配（找"特征在不在"）

### 人话版原理
像"拼图找图"。你有一张小图 = 模板（代码里是 `hole_template.png`，从合格件上截的圆孔）。把这张小图在被检图像上**从上到下、从左到右一格一格滑动**，每到一个位置算一个"相似度分数"，分数最高的位置 = 最像模板的地方。分数够高 → 特征存在（OK）；太低 → 特征缺失（NG）。

### 代码对照
```csharp
Cv2.MatchTemplate(roiMat, _template, result, TemplateMatchModes.CCoeffNormed);
Cv2.MinMaxLoc(result, out _, out double maxVal, out _, out _);
var isOk = maxVal >= _threshold;   // 阈值 0.70
```
- `MatchTemplate` 输出一张"分数图" result，每个像素 = 模板放那儿的相似度。
- `MinMaxLoc` 找分数图里的最大值 maxVal（最像的地方有多像）。
- 0.70 是"像不像"的及格线。

### 为什么用 CCoeffNormed（归一化相关系数）
- 分数范围约 [-1, 1]：1 = 一模一样，0 = 无关，负 = 反相关。
- "归一化" = 先减均值再算相关 → 对**整体亮度变化有容忍**（现场灯暗一点也能匹配）。
- 对比项 SQDIFF 是平方差，**越小越像**，但极怕亮度变化，所以不用。

### 关键参数
| 参数 | 代码里 | 含义 |
|---|---|---|
| 模板 | hole_template.png | 从"和现场同样光照的好件"上截特征 |
| 阈值 threshold | 0.70 | 多像才算数。越高越严（漏检风险↑），越低越松（误检风险↑）|

### 失败场景（面试必讲）
1. **产品旋转 / 翻面** → 模板固定方向，一转角度分数暴跌 → 漏检。解决：多角度模板 / 形状匹配。
2. **光照变化** → 归一化扛一部分，扛不住就漏检。解决：固定光源、补光、用边缘图匹配。
3. **模板和现场图不是同光源拍的** → 分数系统性偏低。解决：现场重新抠模板。

### 一句话讲给面试官
> "模板匹配就是拿标准件的特征小图，在被检图像里滑动找最相似的位置，用归一化相关系数打分，0.7 及格。它快、直观，但怕旋转和光照变化，所以模板必须在现场同光照下抠。"

## 3. DimensionTool — 霍夫圆检测（量"圆孔直径"）

### 人话版原理（两段式）
**第一段 找圆**：圆孔边缘（一圈弧线）上有很多像素点。对任意一个边缘点，它可能是"以某点为圆心、半径 r 的圆"上的点——于是这个点给它所有"可能的圆心"各投一票。所有边缘点投完票，**得票最多的点 = 圆心**，半径在 [minRadius, maxRadius] 内筛选。这就是"霍夫投票"。

**第二段 量尺寸**：圆直径（像素）→ 乘 px→mm 标定系数 → 毫米数 → 和设计直径比，偏差超公差判 NG。

### 代码对照
```csharp
Cv2.GaussianBlur(...);   // 先模糊去噪，圆边缘更平滑
var circles = Cv2.HoughCircles(blurred, HoughModes.Gradient,
    Dp, MinDist, Param1, Param2, MinRadius, MaxRadius);
// 取半径最大的圆 → 直径 = 2r → PixelToMm → 比较公差
```

### 关键参数（面试重点，背下来）
| 参数 | 默认 | 含义 | 调大/调小的影响 |
|---|---|---|---|
| dp | 1.2 | 累加器分辨率 = 图像/dp。1 = 最精确最慢 | 越大越快，越容易丢小圆 |
| minDist | 50 | 两个圆心最小距离 | 太小 → 同一个圆被判多次 |
| param1 | 100 | Canny 边缘检测高阈值（HoughCircles 内部先找边缘）| 越小边缘越多，噪声也多 |
| param2 | 30 | 圆心投票阈值，攒够几票才认 | 越小 → 圆越多（假圆也多）；越大越严格 |
| min/maxRadius | 10/200 | 候选圆半径范围（px） | 范围窄 = 快且准，但要覆盖真实尺寸 |

### 失败场景
1. **边缘被遮挡 / 油污 / 反光** → 圆弧不完整 → 测不到或圆心偏。
2. **光照过曝** → 边缘梯度弱 → 找不到边缘 → 测不到。
3. **有多个相近圆** → minDist 太小会重复报圆（代码取最大半径缓解）。
4. **模糊核太大** → 边缘变钝 → 直径偏小（量出来偏小 mm）。

### 一句话讲给面试官
> "找圆用霍夫圆检测，本质是边缘点向可能的圆心投票、票多者为圆心，param2 控制严格度；找到后直径的像素数乘标定系数换成毫米，和设计值比对公差。量程靠 min/maxRadius 卡，怕的是边缘被污染和光照过曝。"

## 4. DefectTool — Blob 分析（找"划痕和缺口"）

### 人话版原理（四步）
1. **反向二值化**：假设缺陷比正常表面**暗**。`灰度 < 128 → 白`，于是缺陷变白色前景、正常表面变黑。
2. **形态学开运算**（先腐蚀后膨胀）：把"芝麻大的白色噪点"擦掉，保留真正的缺陷团块。
3. **找轮廓**：把每团白色区域当一个对象，找出它的外边界。
4. **按形状分类**：
   - 外接矩形 **长/宽比 ≥ 3** → 细长条 → **划痕**；
   - **圆形度 < 0.6** → 形状不规则 → **缺口**；
   - 都没有 → 这一帧 OK。

### 代码对照
```csharp
Cv2.Threshold(blurred, binary, 128, 255, ThresholdTypes.BinaryInv); // 暗 → 白
Cv2.MorphologyEx(binary, cleaned, MorphTypes.Open, kernel);          // 去噪点
Cv2.FindContours(cleaned, out var contours, ...);                    // 找团块
// 每个 contour: 面积 < AreaMin 跳过; 长宽比 ≥ 3 → 划痕; 圆形度 < 0.6 → 缺口
```
- 圆形度 = 4π × 面积 ÷ 周长²。完美圆 = 1，越扁越不规则越接近 0。

### 关键参数
| 参数 | 默认 | 含义 |
|---|---|---|
| AreaMin | 50 | 小于这个面积的团块不算缺陷（滤噪）|
| ThresholdValue | 128 | 二值化一刀切的亮度分界 |
| ScratchAspectRatioMin | 3.0 | 长宽比 ≥ 这个值 → 划痕 |
| NotchCircularityMax | 0.6 | 圆形度 < 这个值 → 缺口 |

### 失败场景（这个算法最容易翻车，讲它最显专业）
1. **光照不均** → 阴影 / 暗角被当成缺陷 → 误报。解决：加背光、打均匀光源、先背景减除。
2. **反光亮点** → 比周围亮，不在"暗"假设内 → 漏检。
3. **缺陷和目标灰度太接近** → 一刀切阈值分不出来 → 漏检。
4. **划痕太浅** → 灰度差不够，二值化后被擦掉。

### 一句话讲给面试官
> "缺陷检测我用经典图像处理链路：高斯去噪 → 反向二值化（假设缺陷比背景暗）→ 开运算去噪点 → 找轮廓，再用长宽比判划痕、圆形度判缺口。它原理简单、速度快、适合明场下的规则缺陷，但怕光照不均和缺陷与背景灰度接近——这正是我下一步想用深度学习互补的地方。"

## 5. 标定（你的最短板，至少懂概念）

### 现在你在做什么
`Calibration.PixelToMm(px) => px / PixelPerMillimeter`，其中 `PixelPerMillimeter = 15`。
意思：**图像里 15 个像素 = 真实世界 1 毫米**。来源：拍一个已知尺寸的零件，量它占多少像素，除一下。

### 为什么这是"简化版"
它只算了一个**整体缩放系数**，隐含假设：镜头无畸变、相机正对工件无透视。真实相机有：
- **径向畸变**：边缘的像会被拉伸/桶形，图像中心和边缘的"每毫米像素数"其实不一样；
- **透视**：相机歪一点，尺寸就量不准。

### 工程上真正的做法（面试可以说"我正在补"）
**棋盘格标定（张正友法）**：
1. 打印棋盘格标定板，从不同角度拍 10~20 张照片；
2. `FindChessboardCorners` 找每个黑白格角点的像素坐标；
3. `CalibrateCamera` 算出相机**内参**（焦距 fx/fy、主点 cx/cy）和**畸变系数**（k1,k2,k3,p1,p2）；
4. 之后每帧先 `Undistort` 去畸变，或 `UndistortPoints` 把测量点去畸变，再量尺寸。

### 一句话讲给面试官（诚实 + 上进）
> "现在项目里是手填 px/mm 的简化标定，适合演示。我清楚真正的工程标定是张正友棋盘格法——算内参和畸变系数，我计划下一步把 Calibration 升级成自动标定。"
