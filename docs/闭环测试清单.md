# 闭环测试清单

> 目的：把"程序好不好"从 418 条代码层测试，延伸到**数据从头流到尾**的实机走查。
> 2026-10-28 建账。每次大改（触发链路/回写/入库/权限/联锁）后照单过一遍。

---

## 0. 三层测试地形（先分清谁管哪层）

| 层 | 内容 | 怎么跑 | 状态 |
|---|---|---|---|
| **L1 代码层** | 单元 + 集成测试（含架构规则） | `ci.cmd` / `dotnet test`，418 条 | ✅ 自动，每次提交 |
| **L2 UI 冒烟层** | 启动→登录→改密→工程师模式切页 | `tests/VisionStation.UiTests`（FlaUI） | 🔶 自动化中 |
| **L3 闭环数据流层** | **本清单**：帧→入库→回写→界面→审计 | 半自动（工装推流）+ 人工看证据 | 📋 本文档 |

L1 绿 ≠ 闭环通。L1 里每块都是真的，但"七步连起来跑"只有本清单验。

## 1. 前置：环境与工装

### 1.1 启动主程序

```cmd
dotnet build src\VisionStation.App
dotnet run --project src\VisionStation.App
```

注意：改过 appsettings/配方必须 rebuild（配置基于 `AppContext.BaseDirectory`）。

### 1.2 工装

| 工装 | 用途 | 命令 |
|---|---|---|
| `VmSimulator` | 模拟 VM 推帧 | `dotnet run --project tools/VmSimulator -- --port 9100 --count 5 --interval 500 --verdict OK` |
| `rtu_slave.py` | RTU 从站 + ST 逻辑（D100~D106 全套，周期触发） | `python scripts/rtu_slave.py COM4 9600`（需 com0com，配 `Transport: "Serial"`） |
| `RtuProbe` | C# 主站探针（读寄存器对账用） | `dotnet run --project tools/RtuProbe -- …` |

参数速查（VmSimulator）：`--verdict OK|NG`、`--count N`、`--interval 毫秒`、`--image 路径`、`--raw "原始行"`、`--listen`（抓包模式，先关主程序）。

### 1.3 证据采集

```bash
# 数据库（二选一）
sqlite3 <数据根>\visionstation.db "SELECT Id,Verdict,RecipeName,CreatedAt FROM InspectionRecords ORDER BY Id DESC LIMIT 10;"
python -c "import sqlite3;c=sqlite3.connect(r'<数据根>\visionstation.db');[print(r) for r in c.execute('SELECT Id,Verdict,CreatedAt FROM InspectionRecords ORDER BY Id DESC LIMIT 10')]"

# 日志：<数据根>\logs\ 按天滚动；丢帧/断流/审计全在这
```

数据根 = `--data-root` 参数或默认 `%LOCALAPPDATA%` 下目录（启动日志第一行会打印）。

## 2. 主闭环走查（10 个场景）

> 顺序执行。场景 A~E 用默认 `Transport: "Tcp"`（PLC 离线不影响收帧验证）；
> 场景 C/D 需要切 `Transport: "Serial"` + com0com + rtu_slave。

### 场景 A：OK 帧全程（闭环 ⑤→⑥ 的上半）

| | |
|---|---|
| **前置** | 主程序已启动，状态栏平台灯亮（`VmLink` 已监听） |
| **操作** | `dotnet run --project tools/VmSimulator -- --port 9100 --count 5 --interval 500 --verdict OK` |
| **预期** | ① 检测页记录 +5，全部 OK；② 历史页 5 条新记录；③ DB 里 Verdict 全 OK；④ 良率显示 100% |
| **证据** | DB 查询（§1.3）；截图历史页 |

### 场景 B：NG 帧与良率（同上，反向）

| | |
|---|---|
| **操作** | `--count 3 --verdict NG` |
| **预期** | 记录 +3 全 NG；良率从 100% 掉到 5/8=62.5%（累计口径，重启会查基数）；NG 行红色标注；历史页按结果筛选能单独看到这 3 条 |
| **证据** | 良率数字；历史页筛选结果 |

### 场景 C：PLC 触发握手（闭环 ②③⑥ 完整形态）

| | |
|---|---|
| **前置** | appsettings 改 `"Transport": "Serial"`，rebuild；com0com 就绪；先起 `python scripts/rtu_slave.py COM4 9600`（**带触发**，别加 --no-trigger），再启动主程序 |
| **操作** | 让从站周期触发跑 1~2 分钟 |
| **预期** | ① 从站控制台：D100 被置 1 → 被主机清 0（握手完成）；② 主机写回 D101（1/2）→ 从站计入 D103/D104；③ 状态栏 PLC 灯绿；④ DB 记录数 ≈ 触发周期数 |
| **证据** | 从站退出时的统计（Ctrl+C 打印 OK/NG 计数）与 DB 记录数对账 |

### 场景 D：心跳与看门狗（闭环 ⑥ 的 D102）

| | |
|---|---|
| **操作** | 场景 C 运行中，用 RtuProbe 读 D102 两次间隔 1s；然后正常关闭主程序，再读 D102 |
| **预期** | 程序活着：D102 每次 +10 左右（100ms 一跳）；程序关闭：D102 冻结，从站侧 2 个周期后 D105 判离线（从站控制台打印） |
| **证据** | 两次读数差值；从站的离线告警输出 |

### 场景 E：异常路径（闭环的抗打击面）

| # | 操作 | 预期 |
|---|---|---|
| E1 | 推帧中途杀掉 VmSimulator（`--count 100` 跑一半杀） | 主程序**不崩**；10 秒后日志/界面出断流告警（StallTimeoutSeconds） |
| E2 | VmSimulator `--count 200 --interval 20`（快于写库） | 丢弃计数上涨、日志有"累计丢弃"，**到达数 ≠ 入库数但 = 到达数 + 丢弃数**；丢满 5 的倍数上界面 Warning |
| E3 | 推一行乱码（`--raw "garbage"`） | 不崩；入库一条带原因的 NG（解析失败也是结果，不静默丢） |
| E4 | 断流后重启 VmSimulator 再推 | 自动恢复接收，无重启主程序 |

### 场景 F：联锁与急停复位（F-47 验收）

| # | 操作 | 预期 |
|---|---|---|
| F1 | PLC 未接（Tcp 模式 502 无从站）时点"自动模式" | **被拦**：日志逐条给出原因（PLC 离线等），触发源没 Start，无 Start 审计 |
| F2 | 点急停 → 再点"自动模式" | 被拦，原因含"急停未复位"；**「复位急停」按钮出现** |
| F3 | 点「复位急停」→ 再点"自动模式" | 放行，自动运行中；审计有 EStopPressed 和 EStopReset 各一条 |
| F4 | 急停状态下点"停止"/再点"急停" | 永远可用，**联锁不拦安全动作** |

### 场景 G：功能页人工验收（UI 走查欠账清偿）

| # | 页面 | 检查点 |
|---|---|---|
| G1 | 配方页 | 列表与 `Config\recipes` 一致；切换后 `.active` 文件内容变；界面明说"重启后生效"；无权限账号看不到入口 |
| G2 | 用户页 | 新增（强制改密标记）、停用后该账号登录被拒、**不能停用自己**、**不能动最后一个启用管理员**、重置密码后 MustChangePassword |
| G3 | 审计页 | 场景 B/F 产生的动作都能查到；时间/动作/用户名筛选生效 |
| G4 | 空态 | 无记录时历史页不白屏；各页加载失败给人话提示 |

### 场景 H：看门狗（无人值守）

| # | 操作 | 预期 |
|---|---|---|
| H1 | 正常关窗 | watchdog.log 无重启记录（Shutdown 事件被收到） |
| H2 | 任务管理器杀主进程 | 2s 后自动拉起，命令行参数原样重放（`--data-root` 不丢）；watchdog.log 记录一次重启 |
| H3 | 连杀 3 次（10 分钟窗口内） | 第 3 次后停止拉起，watchdog.log 出 CRITICAL |

## 4. 与自动化的边界（哪些将来能收编）

| 场景 | 可自动化？ | 方式 |
|---|---|---|
| A/B 收帧入库 | ✅ 易 | VmSimulator + DB 断言（集成测试已有同构覆盖，缺的是"真进程"版） |
| C/D RTU 握手心跳 | 🔶 中 | RtuProbe 已是主站探针，包一层断言即可 |
| E 异常路径 | 🔶 中 | 快推/乱码可自动化；杀进程类交给看门狗测试 |
| F 联锁 UI | ✅ 易 | 归 UiTests（FlaUI 点按钮读日志面板） |
| G 功能页 | ✅ 中 | 归 UiTests，与并行线汇合 |
| H 看门狗 | ✅ 中 | 起真进程 + taskkill，已有单测钉纯逻辑，缺进程级脚本 |

原则：**能确定性自动的收进 L1/L2；要人眼判断观感的留在本清单**。
