# ADR-001 — 达标线：交付可运行的求职项目

- **日期**：2026-08-16
- **状态**：完成
- **触发**：求职面试用，项目存在多处"当场露馅"硬伤

## 背景

目标岗位：视觉软件 / 上位机工程师。项目架构是王牌，但当前状态不能直接拿去面试——Test 项目构建失败、配方 ROI 自相矛盾、默认 Webcam 无摄像头会自检失败、配置全是绝对路径、非 git 仓库。

## 目标（达标线验收标准）

把项目拷到一台干净电脑后：
1. `dotnet build VisionStation.slnx` 零错误；
2. `dotnet run --project VisionStation.App` 能启动、能出图检测；
3. 能对着项目讲满 30 分钟不卡壳。

## 非目标（本次不做）

- 不加新算法工具、不碰深度学习/GPU、不做可视化编辑器。
- 加分线（通信出口 / 量化指标 / 标定升级 / 补单测）留到后续独立 ADR。

---

## 条目 1 — VisionStation.Test 无法构建

- **问题**：`Program.cs` 引用已删除的 `VisionStation.Core.Detectors`（`PresenceDetector` / `DimensionDetector` / `DefectDetector`），项目编译失败（实测 CS0234）。
- **位置**：`VisionStation.Test/Program.cs`
- **修复方向**：
  1. 删除 `using VisionStation.Core.Detectors;`
  2. 删除旧 detector 创建块（presenceDetector / dimensionDetector / defectDetector，及仅供其使用的 `calibration` 变量），保留新的 `PresenceTool` / `DimensionTool` / `DefectTool` 实例
  3. 设计决策：把 `VisionStation.Test` 加入 `VisionStation.slnx`，让 `dotnet build VisionStation.slnx` 直接覆盖 Test 的构建验证
- **验证**：`dotnet build VisionStation.slnx` 零错误（含 Test）。
- **状态**：已修复（实测 0 错误 0 警告）

## 条目 2 — 配方 ROI 与工具不匹配

- **问题**：`default.json` 的 `rois` 只有 1 个 `"检测区域"(30,30,240,240)`，但三个工具分别声明 `roi:"Presence"/"Dimension"/"Defect"`（均不存在）。Pipeline 三层匹配兜底后三个工具全在 240×240 大 ROI 上跑，误检风险高。
- **根因补充（实测）**：`default.json` 用 camelCase 键，而 `App.xaml.cs:LoadRecipe` 用默认 `JsonSerializerOptions`（大小写敏感）反序列化 → `rois/tools` 全部绑定失败（实测 rois=0 tools=0）→ 永远走内置兜底配方（1 个"检测区域"）→ 三工具靠 Pipeline 兜底全在 240×240 上跑。
- **位置**：`VisionStation.App/Config/recipes/default.json`、`VisionStation.App/App.xaml.cs:LoadRecipe`、`VisionStation.App/ViewModels/RoiEditorViewModel.cs:SaveToFile`
- **修复方向**：
  1. `default.json` 的 `rois` 改为 3 个具名 ROI：Presence(120,120,80,80)、Dimension(120,120,80,80)、Defect(30,30,240,240)（与 `VisionStation.Test/Program.cs` 一致）
  2. `LoadRecipe` 反序列化改用 `PropertyNameCaseInsensitive = true`（或 `JsonSerializerDefaults.Web`），让 camelCase 配方真正加载
  3. 内置兜底配方（`LoadRecipe` 兜底分支）的 `Rois` 同步改为同样的 3 个 ROI
  4. `RoiEditorViewModel.SaveToFile` 序列化为 PascalCase，与大小写不敏感读取兼容；保存路径改走解析后的配方路径（见条目 4），避免写到 bin 副本
- **验证**：跑 Test 全链路，三工具各自在正确 ROI 上执行、结果正确。
- **状态**：已修复（Test 全链路通过：01_good 孔匹配 1.000、02_bad 缺孔 0.047、03_bad 孔偏大 3.13mm；数据库 3 条记录）

## 条目 3 — 默认相机模式改为 File

- **问题**：`Camera:Mode="Webcam"`，无摄像头时启动自检弹"1/2 在线"失败框，演示环境直接崩。
- **位置**：`VisionStation.App/appsettings.json`
- **修复方向**：默认改为 `File` 模式（读 TestImages）。`CameraFactory` 兜底默认本就是 `File`，行为一致。
- **验证**：无摄像头环境启动自检全部通过。
- **状态**：已修复（File 模式读 TestImages 4 张图，自检 5 项全 OK）

## 条目 4 — 配置绝对路径改相对路径

- **问题**：`appsettings.json` 中模板 / 图片 / DB / 日志 5 处全是 `D:\Code\VisionStation\...` 绝对路径，换机器失效。
- **位置**：`VisionStation.App/appsettings.json`（消费点：`App.xaml.cs`、`Services/CameraFactory.cs`、`Services/ServiceCollectionExtensions.cs`、`ViewModels/RoiEditorViewModel.cs:SaveToFile`）
- **修复方向**：
  1. 新增 `VisionStation.App/Services/AppPaths.cs` 统一路径解析：绝对路径原样使用；相对路径基于 cwd 解析（`dotnet run` / 发布目录直接可用）；读资源（模板 / 图库）在 cwd 找不到时回退 `AppContext.BaseDirectory`；配方路径保持 BaseDirectory 优先（兼容发布部署）
  2. `appsettings.json` 5 处改相对：`TestImages` / `TestImages\hole_template.png` / `InspectedImages` / `visionstation.db` / `Logs`
  3. 消费点注入 `AppPaths`：Serilog LogFolder、`CameraFactory.ImageFolder`、`ToolFactory.TemplatePath`、Storage DbPath+ImageFolder、`HealthChecker`、`HousekeepingService`
  4. `RoiEditorViewModel.SaveToFile` 改写到解析后的配方路径（与加载一致）
- **验证**：项目拷到任意目录可正常启动、落库、存图、写日志。
- **状态**：已修复（AppPaths 统一路径解析，配置全部相对化）

## 条目 5 — 初始化 git 仓库 + README

- **问题**：项目非 git 仓库，无法放 GitHub 简历链接。
- **位置**：项目根目录
- **修复方向**：`git init` + `.gitignore`（bin/ obj/ publish/ *.db Logs/ InspectedImages/ crash*.log diag.log .vs/ *.user）；`TestImages`（3 图 + 模板，约 38KB）提交，保证干净克隆后 App 开箱即用（无需先跑 Test 生成图）；README 补充"运行前置"说明。
- **验证**：`git status` 干净、可正常 push。
- **状态**：已修复（git init + .gitignore + README 运行前置，初始提交 49539b0）
