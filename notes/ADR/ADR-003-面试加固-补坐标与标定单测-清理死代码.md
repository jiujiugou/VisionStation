# ADR-003 — 面试加固：补坐标换算与标定单测 + 清理死代码

- **日期**：2026-08-16
- **状态**：已完成
- **触发**：ADR-002 验收复测通过后，按优化流程扫描全项目，发现面试深挖仍有三处可露馅/可清理的点。

## 目标（验收标准）

1. 坐标换算核心算法在 Core 且可独立单测（关闭 ADR-002「后续候选：CoordinateMapperTests」缺口）；
2. 标定 px↔mm 换算有单测；
3. `dotnet build VisionStation.slnx` 零错误零警告；
4. `dotnet test VisionStation.UnitTests` 全绿，且通过数不低于基线 12。

## 非目标

- 不做 FPS 实时展示功能（留后续 ADR）；本次只清理空壳计数，不扩 UI 范围；
- 不动算法行为、不升级依赖、不改对外检测结果。

---

## 条目 1 — 坐标换算核心无法独立单测（CoordinateMath 在 App 层依赖 WPF）

- **问题**：`CoordinateMapper` 在 App 层，`using System.Windows`（`Point/Rect` 便捷重载），
  UnitTests（net8.0，仅引用 Core）无法直接测它；核心换算与 UI 便捷重载耦合在一个类里。
  ADR-002 收尾已明确留此缺口。
- **位置**：`VisionStation.App/Services/Coordinates/CoordinateMapper.cs`
- **修复方向**：把纯数学抽到 `VisionStation.Core/Geometry/CoordinateMath.cs`
  （持有布局参数 + ScreenToImage/ImageToScreen 双向换算，纯 double，零外部依赖），
  App 层 `CoordinateMapper` 改为其 WPF 薄封装（委托 + `Point/Rect`/`ScreenCoordinate/ImageCoordinate` 便捷重载），
  对外 API 不变。
- **验证**：`CoordinateMathTests` 锁定 Uniform 布局、Zoom 钳制、双向换算、越界保护。
- **状态**：已修复

## 条目 2 — Calibration 标定换算无单测

- **问题**：`Calibration`（px↔mm + 公差判定）是 Core 纯数学，面试核心话术点，
  却没有任何单测覆盖。
- **位置**：`VisionStation.Core/Calibration.cs`
- **修复方向**：新增 `CalibrationTests`（像素↔毫米互转、公差内/外判定、除零保护）。
- **验证**：`dotnet test` 对应用例全绿。
- **状态**：已修复

## 条目 3 — DetectionResult 死代码

- **问题**：旧 Detectors 移除后 `DetectionResult` 遗留，全仓库仅自身文件与两处 XML 注释引用。
- **位置**：`VisionStation.Core/Models/DetectionResult.cs`
- **修复方向**：删除文件；同步清理 `IVisionTool.cs`/`ToolResult.cs` 注释里的过时引用。
- **验证**：`dotnet build` 零错误。
- **状态**：已修复

## 条目 4 — MainViewModel FPS 统计空壳

- **问题**：`_fpsCounter`/`_lastFpsReset` 只自增不展示，构造里挂了个每 2 秒空转的 `Timer`。
- **位置**：`VisionStation.App/ViewModels/MainViewModel.cs`
- **修复方向**：删除空转定时器与未使用计数；FPS 实时展示留后续 ADR。
- **验证**：`dotnet build` 零错误零警告。
- **状态**：已修复
