# 这里放 VisionMaster 流程文件（.sol）

## 怎么产出

1. 打开 VisionMaster 客户端 → 新建方案
2. 拖入**图像源**模块，类型选「本地图像」，名字保持 `图像源1`
3. 搭检测链：快速匹配（建模板）→ 位置修正 → 圆查找/测量 → 缺陷检测
4. **判定参数（公差、面积阈值）在 VM 里配** —— 这是唯一真相源，C# 侧不再写一份
5. 另存为 `washer-2448.sol`，放到本目录
   （名字取自配方 `vm.solutionPath`，当前是 `washer-2448.sol`；存错名字 = 自检报"方案文件不存在"）

调试素材：`TestImages/VirtualCamera/2448x2048/` 下的三张 BMP（01 好件 / 02 缺孔 / 03 划伤），
2448x2048 与配方 `sensor` 一致，可直接拖进 VM 的图像源里跑。

**不想自己搭**：`TestImages/VirtualCamera/vm-samples/` 里有 4 份海康自带的示例方案
（`CircleFind.sol` 就带 `图像源1` + `圆查找1`，和本配方声明的模块名一致），
直接双击用 VM 打开就能跑，清单与注意事项见 `docs/引擎集成-说明.md` 第 3.0 节。

## 怎么接上

配方 **`.active` 指向的那份**（当前 `Config/recipes/default-2448.json`，不是 `default.json`）里：

```json
"engine": "Vm",
"vm": {
  "solutionPath": "Config\\solutions\\washer-2448.sol",
  "procedure": "流程1",
  "outputs": [ { "module": "圆查找1", "label": "外径", "role": "Measure", "metric": "外径", "unit": "px" } ]
}
```

模块名、输出名必须和 `.sol` 里一字不差，否则启动自检 / 首帧会明确报"找不到模块「xxx」"。

> **2026-10-27 变更**：`imageSourceModule`、`io`、`ioKind` 三个键已从配方结构中删除。
> 前两个（相机/图像源）是因为本程序不再调 SDK 喂图；`io`/`ioKind` 是 SDK 时代按输出名取值的遗留。
> 老配方里残留这三个键不影响加载，反序列化会忽略未知成员。

详细说明见 `docs/引擎集成-说明.md`。
